# AURUM architecture

## Running components

The Python 3.12+ modular monolith runs as a CLI. The optional dashboard adds a loopback FastAPI process and a local Next.js server. The editable package exposes the `aurum` executable.

Local Compose packaging uses separate unprivileged API and standalone dashboard
containers in one network namespace. Published ports bind to localhost, and the
server-side proxy continues to use a loopback API address. An explicit all-interface
API bind requires an access token. Workers share the persistent data volume and
start explicitly. Hosted CI built and launched both images and verified the
token boundary on 2026-11-11. See `OPERATIONS.md` for remaining host limits.

The dashboard reads immutable dataset candles, paginated evidence, saved reports and monitor health from SQLite through the API.

Staged validation selects from an exclusive availability bound on the backtest journal. It reads frozen manifests without the full replay summary. Final evaluation references the immutable selection and reads the selected candidate's qualified decision journal after embargo. It runs a fresh paper executor over original dated minute bars. The scheduled path runner is shared with matched controls, and the report retains decision sequence IDs and execution events. Backtest diagnostics use closed trade observation order and immutable setup decisions. Analytics v2 groups execution costs, holding times, excursions and completed return dispersion from immutable trades without changing saved backtest IDs. Report views distinguish unpartitioned replay, final holdout, conditional simulations and explicit paper account marks. Price charts use UTC candle closes and map events at or after their availability. The chart projector folds the selected run's causal prefix and ends each overlay at recorded retirement. Strategy-only plans appear as point references. The API supplies source and terminal event sequences. The backtest form uses server-provided domain defaults and submits complete profiles. Saved profiles retain existing run identities. The server-side proxy restricts bearer forwarding to loopback HTTP and rejects cross-origin browser writes. Runtime profiles store variable names and resolve values only in explicitly launched workers. A provider profile pins either an imported dataset calendar or an explicit reviewed dated schedule and contract. The source selector keeps imported history separate from the monitor journal. The monitor chart captures applied and pending status in one short snapshot and reads immutable pages bounded by the captured checkpoint and preserves source counts per aggregate. The monitor audit lists actual observation times and alerts. Market evidence and setup streams have independent sequences. Monitor overlays use the later of source confirmation and durable observation. Schema v10 bounds market projection with the recorded primary analysis count, configured lifetimes and the pinned applied cursor. Schema v11 indexes historical availability and bounds evidence-run lookbacks using complete exchange-aligned bars. Direct monitor, monitor replay and provider profiles can supply the same immutable point-in-time economic snapshot as a backtest. Monitor restart reconstructs context with the identical snapshot. Qualified source-close setups also carry separate observation-time economic risk for alert and new forward-entry eligibility. The applied minute remains independently eligible for processing existing positions. Linked announcements supersede prior versions only from publication onward, and partial coverage cannot establish clear risk. Ordered local iCalendar comparisons preserve per-capture checksum, parser version and observation time. They follow a known UID through rescheduling and require explicit status for cancellation. Composed snapshots retain the normalized inputs' hashes, individual scope and capture history. Events preserve source-local IDs, and revisions remain within one publication. A bundle can flag known releases while retaining partial coverage. Snapshot construction indexes release-time candidates with publication, revision and actual-observation boundaries. Assessment searches the configured release buffer and returns event IDs in the original snapshot order. Forward baseline comparison checks the snapshot as part of rule compatibility. The monitor API and checkpoint stream assess live and delayed heartbeat age at read time. The classification leaves the durable health journal intact and shares the notification claim deadline. Historical carried positions keep their prior prefix.

## Flow and invariants

Schema v15 adds immutable reviewed economic activations for each monitor.
Activation follows all already processed source and observation clocks, and
each snapshot retains its own publication availability. Source context resolves
the activation timeline at candle close. New alert and forward-entry checks
resolve it at processing observation. Restart reads the same timeline while
reconstructing detector state. A missing source is an explicit unknown-risk
activation. The baseline monitor identity remains the original frozen manifest,
and affected journal decisions carry activation IDs. Historical forward
comparison rejects an unmatched adopted economic history.

1. The caller supplies an authorized unadjusted single-contract CSV, source timezone, timestamp labeling, provider, data kind and reviewed schedule. Calendar coverage is the expected export interval. The dated snapshot groups full half-open open windows by exchange trade date. The calendar intersects those windows with coverage for candle validation. Closed intervals are represented by the absence of open windows, and split windows can share a trade date. Legacy snapshots keep their original clipped window representation.
2. Ingestion reads the exact source bytes, validates the fixed CSV schema and every bar, converts UTC or source-local timestamps to UTC, and maps close labels back one minute. Timezone conversion uses the pinned package, and the package version enters dataset provenance.
3. Normalization sorts uniquely timestamped bars and checks each expected open minute, including boundary and entirely absent windows. Invalid rows, duplicates or contract mismatches reject the import. Disorder and zero volume are reported. Gaps are retained as diagnostics and gate replay.
4. A SHA-256 ID covers the raw source checksum, source settings, import version, price basis and normalized schedule. Trade imports preserve the nanosecond UTC instant and unique source sequence. Schema v12 saves the prints with raw bytes and derived candles in one transaction. Schema v13 saves quote series and observations separately, shares raw-source checksum storage and indexes UTC observation time and sequence. Schema v14 archives official economic iCalendar receipts and shares the raw checksum store. Receipt IDs bind the publisher, endpoint, observation clock, archive version and byte checksum. Archive reads verify receipt identity and byte content. Whole-store normalized audit re-parses archived publication bodies and applies the same checks to staged backups. Local preview routes prepare snapshots without writing. Settings copies the reviewed result into the existing profile form. The store saves raw bytes, metadata and candle rows atomically. An identical request resolves to the same dataset and retains its initial import time.
5. The repository reads a dataset in open-time order via an iterator. The CLI emits one stable ID per candle-close event. `available_at` is the historical candle close and models logical availability at close. Actual vendor delivery latency is a future input. Events keep their dated contract and historical/synthetic label. For dated schedules, the CLI resolves the exchange date at the candle open using the stored snapshot.
6. The same incremental aggregator accepts each completed minute from replay or another chronological caller. It holds one running OHLCV bucket per selected timeframe. Intraday buckets restart at each full open window and daily bars combine all expected open windows for a trade date. A bucket publishes at its scheduled close only when every expected minute was observed. The CLI derives aggregate IDs from the dataset, aggregation version, timeframe and bucket open.
7. Structure analysis consumes completed aggregates for one timeframe and contract. It processes breaks against previously confirmed levels before confirming new swings, then updates the classifications. Each event's UTC source opens can be joined to the input dataset's aggregate events for the run timeframe and version. The engine holds bounded pivot and ATR windows and the latest levels per scope.
8. An evidence run also observes completed named-session minutes and daily bars. On an analysis close it evaluates previously mapped levels, structure and imbalances, links strictly earlier eligible sweeps to MSS, and then releases newly known price proxies. Full daily, weekly and named-period coverage is checked before publication. A gap or proxy is never retested by its confirming bar.
9. Strategy replay advances the same evidence stream and completed 15m/1h/4h context before each setup decision. It writes state transitions with source evidence, explicit filters, costs and contextual uncertainty. Setup IDs are stable inside the versioned run. Historical restart recovery can reconstruct active state by replaying the input prefix. Rebuilding a completed definition returns its existing events.
10. Backtest replay processes queued orders and existing positions against each minute before asking the strategy about that minute's close. Entry orders become eligible only after the signal, at the next eligible open under configured latency. The run stores setup transitions, order audit, completed trades and a terminal summary. The manifest records execution, cost and performance versions. The paired intrabar sensitivity report compares immutable trade journals and rejects any other configuration change. An optional intrabar rule reads the source prints only for a dual-touch minute, reconstructs its exact OHLCV, and records the first print crossing the bracket. The detection and minute-level modeled execution clocks stay shared.
11. Research reports join completed trades to their setup timestamps and scores. Split eligibility uses both decision and observed outcome times. Candidate ranking and walk-forward use pre-holdout data. Parameter sensitivity removes a single declared factor from each immutable candidate profile, compares the remaining settings, and projects only pre-holdout evidence. Scenario simulations have their own assumed label, and resampling retains the original backtest provenance.
12. The account ledger consumes explicit paper observations, not trade orders. Session close updates the loss trail and funded sizing tier. Intraday checks compare the selected measurement against the current floor. Payout and phase actions are explicit and separately audited. The same loss trail powers an optional trade-close drawdown Monte Carlo model.
13. Contract analysis filters reviewed listings by effective availability and compares activity over a common measurement period. Continuous series plans reference immutable datasets and explicit switches. Forward adjustment uses a shared close known by the switch and applies only to the successor segment. Streaming a series uses bounded immutable read pages and keeps dated source candles separate. The Reports workspace creates the same immutable contract and continuous reports as the CLI, with point-in-time availability and separately labeled preview prices.
14. The monitor journals normalized and raw frames. The live worker retains the receive clock, samples the processing clock within the write transaction and retries only SQLite busy or locked errors. A retried committed frame records its recovery and stays execution-ineligible. It applies only the contiguous prefix of reviewed open minutes, passing those minutes to the existing strategy engine. Recovered setup events retain their actual observed time and source status. A fresh, connected, real-time close can enqueue a paper alert. Missing data, clock staleness and latched integrity conflicts suspend delivery eligibility.
15. An explicitly started worker filters the alert queue, claims one destination-specific delivery, sends outside the transaction and records the outcome. Health warnings remain eligible during a feed fault. Confirmed paper setups require a fresh monitor check. Ambiguous transport results or expired sending leases become uncertain.
16. Completed reviewed daily, weekly and monthly reports may queue an informational summary in the same transaction as their publication marker. Manual queuing supports saved reports. The report ID determines the alert identity, preserving the first queue clock and destination-level delivery history across restarts. Reports disclose source classification, actual sample, modeled net costs, coverage and uncertainty. The common preferences and delivery audit apply without requiring a current market heartbeat for a past-period report.
17. The native Databento adapter implements the same frame-source boundary as normalized WebSockets. It pins GLBX.MDP3, ohlcv-1m, one explicit raw dated MGC symbol and a verified SDK version. A preceding symbol mapping must match both the raw symbol and timestamp interval. Each accepted minute preserves mapping and OHLCV DBN bytes with its adapter identity and callback receipt clock. Replayed records remain historical until the gateway reports replay completion. Reconnects resolve the next expected reviewed minute and request native intraday replay only inside a conservative 23-hour horizon. Longer gaps stop rather than purchase history or discard missing minutes. Overflow and slow-reader errors latch integrity faults. The adapter recognizes transient socket/timeout exceptions wrapped by the pinned SDK through their types and bounded causal chain; unqualified authorization failures remain permanent. Provider error text is not retained. Stream startup suspends prior-process readiness before opening a transport. No price is fabricated for a vendor's omitted no-trade interval.
18. Provider profiles can select native Databento with an explicit raw symbol and environment variable name for its key. Native profiles enforce real-time classification and exclude normalized endpoint/backfill settings. Saving validates only local configuration. An explicitly launched profile worker binds the same durable resume logic as the direct command. Profiles without native fields retain their previous serialized definitions and IDs.
19. Monitor input verification reconstructs normalized/replay candles and serialized native SDK records without a network client. It compares exact saved candles, dated identity, reviewed continuity and known receipt/application clocks. Native records reuse the production decoder with the original pinned adapter/SDK. A bounded input snapshot tolerates later append-only arrivals and rejects a gap fill changing its captured count. Whole-store verification and private backup checks include this audit. Restart validates each source row before feeding the detector and latches an integrity fault on mismatch. Unknown legacy observation clocks are counted. This input audit does not reproduce detector-event journals or independently verify source entitlements.
20. A real-time monitor may explicitly enable setup lifecycle alerts. The disabled default is omitted from identity serialization, preserving prior monitor/profile IDs. At each source close only the last stage per setup may queue a developing notice, with freshness and observation-risk gates. Confirmed alert IDs and paper eligibility are unchanged. Invalidated/expired setups previously announced as developing cancel local pending/retry deliveries and queue an informational withdrawal, including when recovered history establishes the invalidation. Withdrawals disclose source class and actual observation, bypass current quote freshness and score/session filters, and retain severity/quiet/expiry/rate controls. No already accepted external message is recalled.

## Current database

SQLite 3.37+ is required for STRICT tables. The AURUM application ID and SQLite user version identify the database. Read commands open in read-only mode, and earlier input schemas remain readable. The first write applies pending migrations through v16 transactionally. Writes use an immediate transaction, foreign keys and rollback on error.

- `source_blobs` keys raw CSV bytes by SHA-256 and deduplicates repeated source content.
- `datasets` keys records by dataset ID and references the source blob. It stores versioned provenance with the normalized schedule, actual range, import time, count, quality issues and replay eligibility. The calendar format has its own independent version in provenance JSON.
- `candles` uses `(dataset_id, opened_at)` as its primary time-series index. OHLC values are integer ticks. Contract identity is inherited from the dataset.
- `structure_runs` records a content-addressed run definition covering dataset, timeframe, exact rule configuration and implementation versions. `structure_events` stores ordered evidence keyed by run and sequence. Strategy transitions reuse the same tables with a versioned strategy manifest. Run and event writes commit together. Replay and canonical serialization happen in a bounded private spool outside the write transaction.
- `analysis_reports` stores content-addressed report definitions and results. Validation and resampled reports reference immutable backtest IDs. Assumed scenarios are reproducible without a dataset.
- `monitor_runs`, `monitor_minutes`, `monitor_events` and `monitor_alerts` keep source definition, durable cursor, pending frames, transition audit and deduplicated in-app alerts. Advance of the cursor, applied minute and resulting events commit together. Restart reconstructs immutable applied pages outside the write transaction and catches up any new committed tail before ingestion. Historical recovery and offline replay use transactions of at most 256 frames. The same minute path records each frame and its observation evidence. Live frames commit individually. Schema v6 adds `monitor_market_events` and nullable observed timestamps on applied minutes. Previous rows keep unknown observation times.
- `forward_paper_research` reports freeze a forward cursor and event sequence. They attribute events to source-minute exchange trade dates and separate descriptive comparisons, missing coverage and unresolved outcomes. Independent historical baselines must predate registration and match strategy and cost assumptions. Schema v8 records idempotent completed-period publications. Earlier reports are anchored to their own source-minute period end.
- `forward_runs` and `forward_events` persist the registration boundary, execution settings, cursor and paper audit. Schema v7 stores whether a monitor minute was directly and promptly applied. Forward runs leave interrupted positions unresolved.
- `runtime_profiles` stores immutable provider and delivery settings with variable names only. Schema v9 preserves existing monitor and forward identities.
- Schema v16 adds `economic_pollers` and `economic_poll_attempts`. A transaction claims the next due fetch, then releases the database before HTTP. Receipt archival and attempt completion remain separate so interruption preserves source evidence and an expired claim becomes uncertain. Restart retains due time and exponential backoff. Read-only health and Settings distinguish failed, interrupted and overdue capture. A fresh public receipt still requires review and cannot establish complete economic coverage. Whole-store normalized verification reconstructs cadence and terminal state from the attempt journal.
- `notification_deliveries`, `notification_attempts` and `notification_cancellations` track claims, provider results, retries, expiry and queued cancellation. Destination keys are hashes. Tokens and webhook URLs remain in environment-managed configuration.

The import parser holds a CSV and its normalized rows in memory. SQLite is a local, single-machine deployment. Schedule, provider and contract assertions are caller supplied.
